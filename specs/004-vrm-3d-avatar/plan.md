# Implementation Plan: 3D VRM Avatar Portrait

**Branch**: `004-vrm-3d-avatar` | **Date**: 2026-08-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-vrm-3d-avatar/spec.md`

## Summary

Add a per-assistant "3D Avatar" portrait mode that renders a VRoid-exported `.vrm` file in the portrait panel and drives its facial blendshapes from the existing LLM emotion tag system. The image portrait mode is unchanged. All research decisions are documented in [research.md](research.md).

## Technical Context

**Language/Version**: PHP 8.4 / JavaScript (ESNext) / React 19

**Primary Dependencies**: Laravel 13, React Three Fiber, `@pixiv/three-vrm`, Three.js (new), existing Sanctum auth

**Storage**: PostgreSQL (portrait_type column, vrm_files table) + public disk file storage (same as emotion images)

**Testing**: Pest 4 (backend API), Vitest or Jest (frontend utility functions)

**Target Platform**: Web browser (WebGL required for 3D rendering)

**Performance Goals**: VRM model renders within 5 seconds on broadband; expression transitions complete within 500 ms

**Constraints**: 50 MB max VRM file size; no server-side 3D rendering

**Scale/Scope**: Per-assistant configuration; single VRM file per assistant; no per-user VRM customisation

## Phases

### Phase A: Backend Foundation

1. Create `AssistantPortraitType` enum (`Image`, `Avatar3d`)
2. Migration: add `portrait_type` to `assistants` (string, default `'image'`)
3. Migration: create `vrm_files` table (polymorphic — see [data-model.md](data-model.md))
4. Create `VrmFile` model + factory
5. Update `Assistant` model: add `portrait_type` to `fillable` + `casts()`, add `vrm()` MorphOne
6. Create `AssistantVrmController` (`store`, `destroy`) with user-scoped auth
7. Register routes: `POST /api/assistants/{id}/vrm`, `DELETE /api/assistants/{id}/vrm`
8. Update `AssistantController::update` to accept `portrait_type`
9. Update `AssistantController::show` to return `portrait_type` and `vrm_url`
10. Update `EmotionController::index` — change response from flat array to envelope with `portrait_type`, `vrm_url`, `emotions`
11. Write `AssistantVrmTest` (Pest feature test)
12. Run Pint

### Phase B: Frontend — Data Layer

1. Install npm packages: `three`, `@react-three/fiber`, `@pixiv/three-vrm`
2. Update `useEmotions` hook: consume new envelope response, expose `portraitType` and `vrmUrl`
3. Update `AuthenticatedLayout`: pass `portraitType` and `vrmUrl` to `Portrait`
4. Create `vrmExpressions.js` with the emotion→blendshape mapping (see [research.md](research.md))
5. Update `EditAssistantPage`: portrait type toggle (radio/select), VRM file upload field, wired to the new VRM endpoints
6. Update `CreateAssistantPage`: same portrait type toggle (optional at creation — defaults to image)

### Phase C: Frontend — 3D Rendering

1. Create `VrmAvatar.jsx`:
   - R3F `<Canvas>` filling the portrait container
   - Load VRM via `GLTFLoader` + `VRMLoaderPlugin` from `@pixiv/three-vrm`
   - Camera positioned for bust/portrait framing
   - Ambient + directional lighting
   - `useFrame` loop: lerp current blendshape values toward targets; idle blink accumulator
   - On load error: render fallback image
2. Update `Portrait.jsx`: when `portraitType === 'avatar3d'` and `vrmUrl` is non-null, render `<VrmAvatar>`; when `vrmUrl` is null, render default VERA avatar image
3. Wire `emotion` prop from `Portrait` through to `VrmAvatar`, which calls `getBlendshapeTargets(emotion)` to update targets

### Phase D: Lint & Verification

1. Run `vendor/bin/pint --dirty --format agent`
2. Run `php artisan test --compact --filter=AssistantVrm`
3. Manual verification per [quickstart.md](quickstart.md) scenarios 1–7
